# Releases

Run `npm ci`, `npm run check`, and `npm pack --dry-run`. Create a Changeset for each public change, run `npx changeset version` in a version PR, review the changelog, and merge after CI. A maintainer creates a protected tag `v<package.json version>` on that main commit. The tag is the only publish trigger.

`release.yml` checks out that commit on a GitHub-hosted runner, checks tag/version and main ancestry, runs the full suite and package validation, checks GitHub Packages for an existing version, packs an exact tarball, publishes it to `https://npm.pkg.github.com` under `next`, downloads the published tarball to verify its version and SHA-512 integrity, then creates a GitHub Release. The tag must point to a commit on `main`; pushing the tag triggers the workflow. Issue a corrective version if a published version needs changes. No publication is claimed yet.

The workflow uses its built-in `GITHUB_TOKEN` with `packages: write`; no npm token or npm Trusted Publishing setup is needed. The package name and scope must be lowercase (`@b42y/core`), and the `repository.url` must point to `B42y/b42y-core` so the package is linked to this repository. If the organization disables automatic package permission inheritance, grant this repository Actions access to the package in GitHub Packages settings.

Set required reviewers on the `npm-release` environment and protect release tags. From the reviewed main commit, push `v<package.json version>` (for example, `v0.1.0`). A tag on an unrelated commit fails the ancestry check. If that version already exists in GitHub Packages, the workflow rejects the duplicate. Tags created before this workflow change contain the earlier workflow and do not pick up these changes when rerun.

New GitHub npm packages are private by default. If the package should be public, change its visibility in GitHub Packages settings after the first publish. Installing from GitHub Packages still requires authentication, even for public packages. In another GitHub Actions repository, grant that repository read access to this package and configure `packages: read`, `registry-url: https://npm.pkg.github.com`, `scope: "@b42y"`, and `NODE_AUTH_TOKEN: ${{ github.token }}` for the install step. For local installs, use a GitHub personal access token (classic) with `read:packages` and `npm login --scope=@b42y --auth-type=legacy --registry=https://npm.pkg.github.com`.

For CI push and manual jobs, repository or organization variable `SELF_HOSTED=true` requires a runner with labels `self-hosted`, `linux`, `x64`, and `b42y-core`. Pull requests always run on GitHub-hosted `ubuntu-latest` because their code is untrusted. The publish job also ignores `SELF_HOSTED`. `b42y-app` should install a specific verified version rather than a floating tag for production integration.
